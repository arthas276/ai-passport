# 离线验证码

这块 FoloToy AI Passport 可以离线显示 6 位 TOTP。适合演示或低风险账号；它没有安全芯片，密钥只放在普通 NVS Flash 中，也不能代替银行或工作账号使用的安全令牌。

## 使用

开机后直接进入账号列表，不经过硬件测试菜单。

- 上、下：移动选择或切换当前字符。
- OK 单击：进入、确认或添加一个字符。
- OK 长按：返回；在密钥页表示完成录入——已校时的设备随后显示验证码核对页，再按 OK 才保存；在时间页表示开始校验。
- 20 秒无操作背光变暗，60 秒后进入深睡。任一按键唤醒。

添加账号时，名称用大写字母、数字和空格，选 > 后进入密钥页；密钥使用 Base32，输入中每 4 个字符分为一组显示，便于逐组核对。完成录入后，已校时的设备会先显示该账号当前的验证码（OK 保存，长按取消）：与手机上的验证器比对一致再保存，输错当场就能发现。时间页要先已有一个账号，再输入另一台可信设备上当前的 6 位码。已校准过的设备只搜索前后约两分钟的窗口；从未校准（新机或断过电池）则在锚点时间起的窗口内全量搜索匹配码（通常数秒，最久约一两分钟，屏幕显示进度）。匹配后写入系统时间，此后由 RTC 慢时钟在深睡与重启之间持续走时。

三键输入 Base32 太容易错，因此联机是更好的路径（v1.2）：打开菜单第 4 项「电脑联机」，在连着的电脑上运行 `tools/otp_tool.py`——`add` 用键盘把名称与密钥发进去，也可以直接粘贴 `otpauth://` 链接或用 `--qr` 解码服务方二维码截图（v1.3）；`time` 直接同步电脑时钟（无需码搜索），`del`、`list` 管理账号，`export` 逐账号打印 Base32 密钥供备份或迁移（v1.4）。新增成功后联机页会实时显示该账号的当前验证码，方便当场与手机比对（v1.3）。串口只在该页开启时收指令；应答永不回显密钥，唯一的例外是显式的 `export`，且只在该页物理开启时应答——与 `add` 同一道门，何况 USB 本就能读到 Flash。`otp_tool.py batch` 可在单次串口连接里跑多条指令（Windows 下每多开一次口都会复位板子）。纯离线场景仍可走按键流程。

`tools/otp_ble.html`（v1.5）把同一条控制台搬进手机：电脑联机页开启时设备以 OTP-LINK 广播；Chrome、Edge、Android Chrome 连接配对（加密，Just Works）后无需 USB 即可 `time`、`add`、`list`、`export`——电池耗尽后重新对时、手机直接导入密钥都靠它。iOS Safari 不支持 Web Bluetooth，用 nRF Connect（NUS UUID 6E400001/02/03-…）替代。未加密连接拒收写入，且两个通道都只在联机页开启时应答。

重启（含深睡唤醒）后账号、密钥与时间都还在。整片烧录或擦除 NVS 会清空它们；合并镜像从 `0x0` 烧录时尤其可能发生，这是正常烧录影响，不是验证码算法重置。只有断开电池才会丢时间，届时重新校准即可。

## 实现

应用代码在 `main/otp_core.c`、`otp_store.c`、`otp_power.c`、`otp_link.c` 和 `otp_app.c`。算法与联机指令解析均与界面分开：RFC 6238 与协议测试不需要板卡。界面使用独立的深色页面和 20 px 霞鹜文楷子集，不复用基线测试菜单。

板级引脚、按键窗口、屏幕和睡眠顺序仍使用 BSP。GPIO0 继续只由按键 BSP 持有，深睡前调用已有终端关闭接口。

## 边界

- 没有独立 RTC。深睡与重启期间由 RTC 慢时钟继续走时（有轻微漂移，重新校准即可纠正）；断开电池会丢时间，需重新校准。搁置多年后才重新校准的设备可能超出搜索上界而校验失败。
- 没有安全元件。能读写 Flash 或接入 USB 的人可能提取密钥。
- 蓝牙通道用 Just Works 配对（无带外 MITM 防护）；补偿控制是物理开启的联机页与短时广播窗口。高价值账户本就不建议放本机。
- 不联网，因此不能防钓鱼页面，也不能远程吊销一枚已复制的密钥。
- 已校准设备的时间校验只搜索当前输入前后约两分钟，超出范围显示校验失败，不会把错误时间写成有效时间；全量搜索取第一个匹配窗口，匹配后立即显示当前码，可与可信设备核对。

主机测试覆盖 RFC 测试向量、Base32 和空闲休眠门槛。真机还要检查中文显示、三键手感、深睡唤醒，以及掉电后的记录是否仍在。
