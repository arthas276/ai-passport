# Offline slang dictionary

This is a small offline dictionary for the FoloToy AI Passport. 197 curated common internet slang phrases and a one-line explanation are compiled into the firmware. It works without a network and does not follow the day's trending list.

## Use

Startup opens the word list. It does not enter the hardware-test menu.

- UP and DOWN move through entries or the current initial; OK also steps to the next entry.
- A long OK opens letter filtering from the list and restores the full list from the letter page.
- Every entry shows on one card: the phrase, its reading/initial, and the one-line explanation with a short gloss — no separate detail page.
- The backlight dims after 20 idle seconds and the device deep-sleeps after 60. Any button wakes it.

Letter filtering uses the pinyin initial; the picker lists only letters that have entries. `Y` lists entries whose initial is Y, including YYDS. There is no keyboard, so the letters themselves move with UP and DOWN.

## Content boundary

The entries are short explanations written for this application. They are not copied from the discontinued Xiaojicidian or from another dictionary. There is no submission flow and no live ranking. Usage changes, so this edition only keeps phrases that are still common enough to browse with three buttons.

## Implementation

Lookup lives in `main/slang_core.c` and the pages live in `main/slang_app.c`. The screens are dark word cards, not the baseline test menu. The 16 px and 20 px fonts are generated by `tools/build_slang_font.py` from LXGW WenKai Regular v1.530 (OFL); that source font is not committed. A missing glyph fails the generator, and the packed bitmaps declare `stride = 1` (byte-aligned rows) to match the packer.

On-device checks still need to cover Chinese rendering, button feel, and wake from deep sleep.

## v1.3 "Night Reading" design spec (derived with ui-ux-pro-max)

The 2026-10-29 first on-device pass found two issues, both handled in-tree: Latin letters and punctuation sat off-baseline inside mixed lines (the font generator's ofs_y formula was wrong; fixed to ofs_y = bitmap_top - box_h per LVGL's y1 = line_top + (line_height - base_line) - box_h - ofs_y, using the face's real ascender/descender metrics), and the UI was redesigned.

Tokens (deep-navy night theme, all AA):

| token | value | use | contrast on card |
| --- | --- | --- | --- |
| bg | #102033 | page background | — |
| surface | #1A2E48 | entry card | — |
| border | #2A4A6E | card edge / divider | — |
| gold | #F2C14E | top status / big letter | 8.2:1 |
| body | #F7F4EC | entry / gloss | 12.5:1 |
| secondary | #D7E2EA | reading / battery | 10.4:1 |
| muted | #8EA0B0 | hints / index | 5.1:1 |

Layout budget (240x320): top bar y=10 (left "197 entries" in gold, right battery right-aligned); card x=12 y=40 w=216 h=212 r=16 with title 20px (longest entry 8 chars, single line), reading line +16,+84 16px (pinyin only when the reading equals the title — 194/197 entries; "reading · pinyin" otherwise, worst case 115 px), divider +116, gloss +128 16px (up to 16 chars = 2 lines to y=168), short gloss +176 16px (max 6 chars, single line to y=196); letter page centered big letter; footer y=292 with left hint and right-aligned index. Line height comes from real font metrics (16 px → 20, 20 px → 25); the field-length caps (8/8/7/6/16 across title/reading/pinyin/short_gloss/gloss) were measured across all 197 entries and are enforced by host tests.

Per repo convention, the tokens and budgets above were derived with the ui-ux-pro-max skill before touching UI code.
